# Initial extraction candidate: validation

The initial results below describe a local, unpublished first milestone of the
self-owned engine migration. Later slices are recorded chronologically below.
Current source distribution is described in
[development-branch packaging](development-branch-packaging.md).
It is not the completed shared live VT engine or a releasable family update.

## Inputs and tools

- Original repository revisions are recorded in `family-baseline.json`; remote
  HEAD checks matched those revisions when validation resumed.
- Rust stable 1.99.1 and Rust 1.86.0 were installed in task-local directories.
- Official Debian trixie packages were downloaded against signed repository
  metadata and extracted locally, without installation or package scripts.
  Native checks used GTK 4.18.6, GLib 2.84.4, libadwaita 1.7.6 and VTE 0.80.1.
- Frontend checks used private manifest/lock mirrors, a local `jterm_core`
  override, the sibling engine, and existing vendor patches. Original release
  pins, source snapshots, Nix hashes and Flatpak Cargo inputs were not changed.
- Standalone engine Cargo.lock was generated by Cargo. Frontend candidate locks
  were generated only in the private validation mirrors, not hand-edited.

## Core full-suite result and baseline comparison

The candidate's attempted all-target/all-feature test run stopped at the library
suite: **2,028 passed, 45 failed, five ignored**. Consequently later test targets
were not certified by that command.

The unmodified core at the recorded Git revision was then tested under the same
cloud environment and features: **2,026 passed, the identical 45 failures, five
ignored**. There were no candidate-only failures. The two additional passing
candidate tests are the WakeSink tests.

Most failures reject the environment's system-Git directory ownership. Other
failures involve restricted socket/process operations, the systemd/cgroup scope,
and existing local-probe behavior. These guards were not weakened, bypassed or
converted into passing/skipped tests. The full suite remains non-green here.

## Corrected validation runner behavior

Cargo options for external subcommands must follow the subcommand. Placing the
local patch before `clippy` caused its inner Cargo invocation to resolve the
published core instead of the candidate. `family-cargo.py` now forwards patch and
offline options after the selected command, with a regression check. The final
Clippy checks used the actual candidate and then succeeded with `--locked`.

## Not yet validated or delivered

- Real X11/Wayland windows, Chinese IME, screen presentation latency, real
  application rendering and interactive Vim/tmux acceptance. The cloud test
  shell has no DISPLAY or WAYLAND_DISPLAY.
- A complete shared parser/state/mode/input owner or complete SessionRuntime.
- Frost grid migration, Tauri Canvas frontend, shared GTK renderer, Anvil renderer
  migration, ordinary-shell persistence or cross-platform support.
- Independent application release/CI packaging. Ember/Frost currently use a
  provisional sibling path dependency, and new WakeSink consumers require the
  local core override. They must not be released against the unchanged public pin.
- New immutable engine/core publication, release pins, Nix hashes and Flatpak
  source updates. No commit was pushed, no PR created, no merge/deploy performed.

## Lossless publication fixture compaction

The three large captured parser/semantic fixtures were reversibly interned from
35,980,733 to 773,601 bytes. Re-expansion reproduces every original byte and
SHA-256; no expected value was recaptured or changed. The checked-in utility
`scripts/intern-oracle-fixture.py` supports independent reconstruction. All three
original oracle comparisons, four decoder tests, both frontend test compilations
and all-target Clippy pass after the format-only change.
